## 🎯 Обзор

Набор инструментов для работы с конфигурациями 1С:

1. **🎨 Веб-интерфейс (Streamlit)** - UI для парсинга и объединения конфигураций
2. **`parse_1c_conf.py`** - Парсер конфигурации 1С в структурированный формат
3. **`merge_config_with_extension.py`** - Объединение основной конфигурации с расширениями
4. **`check_annotations.py`** - Проверка корректности обработки аннотаций расширений

## 🚀 Быстрый старт

### Через веб-интерфейс (рекомендуется)

Парсер работает в Docker-контейнере `parser-1c` (Python на компьютере не нужен):

```bash
start.bat                              # весь MCP-1C_INIT (из корня проекта)
docker compose up -d --build parser    # только парсер
```

Откройте http://localhost:8504. Входные выгрузки — `parser/in_conf/` (в контейнере `/data/in_conf`),
результат — `parser/out_conf/` (`/data/out_conf`).

### Через командную строку

Команды выполняются внутри контейнера (`docker exec -it parser-1c bash`),
пути — контейнерные (`/data/in_conf/...`, `/data/out_conf/...`).

**Парсинг одной конфигурации:**
```bash
python parse_1c_conf.py <путь_к_конфигурации> <путь_для_результатов>
```

**Объединение с расширением:**
```bash
python merge_config_with_extension.py <основная> <расширение> <результат>
```

## 🎨 Веб-интерфейс

### Запуск

Контейнер `parser-1c` из `docker-compose.yml` проекта MCP-1C_INIT (порт 8504). Прежние скрипты локального запуска через venv перенесены в `old/parser/`.

### Возможности

- 📂 Работа с локальными папками (ZIP архивы или распакованные конфигурации)
- 🔀 Автоматическое объединение конфигураций с расширениями
- 🚀 Последовательное применение множественных расширений с изменяемым порядком
- 📊 Статистика и метрики в реальном времени
- 💾 Автоматическое сохранение результатов в `out_conf/`

### Работа с файлами

**Входные файлы:**
- Поместите ZIP архивы или распакованные папки в `parser/in_conf/`
- Поддерживаются ZIP и папки с `Configuration.xml` (до 2 уровней вложенности)

**Выходные файлы:**
- Результаты сохраняются в `parser/out_conf/parsed_<имя_конфигурации>/`
- Создаются архивы для основной конфигурации, расширений и объединенного результата
- Структура: `modules/`, `metadata/`, `markdown/`, `modules_metadata.json`, `objects.csv`

## 📚 Скрипты

### `parse_1c_conf.py`

Парсинг конфигурации 1С в структурированный формат.

**Использование:**
```bash
python parse_1c_conf.py <config_dir> <output_dir>
```

**Параметры:**
- `config_dir` - путь к выгруженной конфигурации
- `output_dir` - путь для сохранения результатов

**Что делает:**
1. Парсит XML метаданных всех объектов
2. Извлекает код из модулей
3. Анализирует процедуры и функции (все, не только экспортные)
4. Инжектирует аннотации из XML форм (события с `callType`)
5. Создает `modules_metadata.json` с границами процедур/функций
6. Генерирует CSV для векторизации
7. Создает Markdown описания
8. Архивирует результаты

**Результат:**
```
output_dir/
├── objects.csv              # Список объектов для векторизации
├── modules_metadata.json    # Метаданные модулей с границами процедур/функций
├── modules/                 # BSL код
├── metadata/               # JSON метаданные объектов
└── markdown/               # Markdown описания
```

### `merge_config_with_extension.py`

Интеллектуальное объединение основной конфигурации с расширением.

**Использование:**
```bash
python merge_config_with_extension.py <main_config> <extension_config> <output_dir>
```

**Параметры:**
- `main_config` - путь к основной конфигурации
- `extension_config` - путь к расширению
- `output_dir` - путь для сохранения результатов

**Что делает:**
1. Парсит основную конфигурацию и расширение (с кэшированием)
2. Объединяет метаданные (реквизиты, процедуры, определяемые типы)
3. Интеллектуально объединяет код модулей:
   - `&Перед` - вставляет код в начало процедуры
   - `&После` - вставляет код в конец процедуры
   - `&Вместо` - заменяет тело процедуры
   - `&ИзменениеИКонтроль` - заменяет процедуру с обработкой `#Вставка`/`#Удаление`
4. Перепарсивает объединенные модули для актуальных границ процедур/функций
5. Создает `modules_metadata.json` для объединенной конфигурации

**Результат:**
```
output_dir/
├── <main_name>/            # Основная конфигурация
├── <ext_name>/             # Расширение
└── merged/                 # Объединенный результат
    ├── modules_metadata.json
    ├── objects.csv
    └── modules/
```

### `check_annotations.py`

Проверка корректности обработки аннотаций из XML событий форм.

**Использование:**
```bash
docker exec -it parser-1c python check_annotations.py
```

**Что проверяет:**
1. Находит все `Form.xml` с событиями (`callType`)
2. Проверяет, что аннотации добавлены в BSL файлы расширения
3. Выводит статистику успешности

## 📦 Установка

### Требования

- Python 3.7+
- Конфигурация 1С, выгруженная в файлы

### Зависимости

Все необходимые библиотеки указаны в `requirements.txt`. Для веб-интерфейса требуется Streamlit.

**Установка:**
```bash
cd parser
pip install -r requirements.txt
```

### Формат выгрузки 1С

Конфигурация (и расширения) выгружаются в файлы штатными средствами платформы:
- Конфигуратор → *Конфигурация → Выгрузить конфигурацию в файлы* (формат «Иерархический»);
- или из командной строки:
```
"C:\Program Files\1cv8\<версия>\bin\1cv8.exe" DESIGNER /F "<путь к базе>" /N "<пользователь>" /DumpConfigToFiles "<папка выгрузки>"
```
Для расширения добавьте параметр `-Extension <ИмяРасширения>`.

Структура должна быть примерно такой:
```
ut/
├── Configuration.xml
├── Documents/
│   ├── ЗаказПоставщику/
│   │   ├── ЗаказПоставщику.xml
│   │   ├── Ext/
│   │   │   ├── ObjectModule.bsl
│   │   │   └── ManagerModule.bsl
│   │   └── Forms/
│   │       └── ФормаДокумента/
│   │           └── Ext/
│   │               ├── Form.xml
│   │               └── Form/
│   │                   └── Module.bsl
├── Catalogs/
└── ...
```

## 🔍 Примеры использования

### Пример 1: Парсинг конфигурации через веб-интерфейс

1. Поместите ZIP архивы в `parser/in_conf/`
2. Запустите `start.bat` в корне MCP-1C_INIT (или `docker compose up -d --build parser`)
3. Откройте http://localhost:8504
4. Выберите конфигурации из списка и запустите парсинг
5. Результаты будут в `parser/out_conf/parsed_<имя>/`

### Пример 2: Объединение с расширением

```bash
cd parser
python merge_config_with_extension.py \
    ../in_conf/ut \
    ../in_conf/ut_aa \
    ../out_conf/merged
```

Результат: объединенная конфигурация с обработанными аннотациями расширений в `../out_conf/merged/merged/`

### Пример 3: Повторный запуск с кэшированием

При повторном запуске парсер автоматически использует уже распарсенные данные (если найдены `objects.csv` и `modules_metadata.json`), что значительно ускоряет работу.

## 🔑 Ключевые особенности

### 1. Инъекция аннотаций из XML

Парсер автоматически добавляет аннотации в BSL код при обнаружении событий с `callType` в XML формах:

**XML форма:**
```xml
<Events>
  <Event name="OnCreateAtServer" callType="After">ааПриСозданииНаСервереПосле</Event>
</Events>
```

**Результат в BSL:**
```bsl
&После("ПриСозданииНаСервере")
Процедура ааПриСозданииНаСервереПосле(Отказ, СтандартнаяОбработка)
    СкрытьСуммовыеПоказетели();
КонецПроцедуры
```

### 2. Интеллектуальное объединение кода

Обработка операторов `#Вставка` и `#Удаление` в аннотации `&ИзменениеИКонтроль`:

```bsl
// В расширении:
&ИзменениеИКонтроль("ПриЗаписи")
Процедура ааПриЗаписи(Отказ)
    ПроверкаДанных();
    #Вставка
    НоваяПроверка();
    #КонецВставки
    #Удаление
    СтараяПроверка();
    #КонецУдаления
КонецПроцедуры

// В объединенной конфигурации:
Процедура ПриЗаписи(Отказ)
    ПроверкаДанных();
    // ─── ДОБАВЛЕНО В РАСШИРЕНИИ [ut_aa] ───
    НоваяПроверка();
    // ─── КОНЕЦ ДОБАВЛЕНИЯ [ut_aa] ───
    // ═══ ЗАКОММЕНТИРОВАНО В РАСШИРЕНИИ [ut_aa] ═══
    //СтараяПроверка();
    // ═══ КОНЕЦ ЗАКОММЕНТИРОВАННОГО КОДА [ut_aa] ═══
КонецПроцедуры
```

### 3. Актуальные границы процедур

После объединения кода парсер автоматически перепарсивает модули для получения актуальных границ процедур/функций, что гарантирует корректность `modules_metadata.json`.

## ⚙️ Конфигурация

### Изменение путей

В контейнере папки заданы переменными окружения `INPUT_CONFIGS_DIR=/data/in_conf` и
`OUTPUT_CONFIGS_DIR=/data/out_conf`. Чтобы брать выгрузки из другой папки на диске, поменяйте
левую часть томов сервиса `parser` в `docker-compose.yml`, например:

```yaml
volumes:
  - D:/1C/Выгрузки:/data/in_conf:ro
  - ./parser/out_conf:/data/out_conf
```

## 🔄 Интеграция с Loader

Результаты парсинга используются загрузчиком (`loader/loader.py`) для индексации в Qdrant:

1. **Парсинг** → создает `modules_metadata.json` и структуру папок
2. **Загрузка** → использует `modules_metadata.json` для быстрого извлечения процедур/функций
3. **Индексация** → создает эмбеддинги и загружает в Qdrant

Файл `modules_metadata.json` содержит все необходимые данные для быстрой загрузки без повторного парсинга кода.
