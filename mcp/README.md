## 🎯 Обзор

MCP 1C RAG Server предоставляет набор инструментов для семантического поиска по конфигурации 1С:

- 🔍 **Поиск объектов** - поиск по именам, описаниям, структуре и связям
- 💻 **Поиск в коде** - семантический поиск по модулям и чанкам кода
- ⚙️ **Поиск процедур** - прямой поиск процедур и функций с полным кодом
- 🔗 **Анализ зависимостей** - анализ вызовов между процедурами
- 📊 **Диагностика** - проверка состояния базы данных
- 📖 **Синтакс-помощник** - поиск по документации платформы 1С

## 🏗️ Архитектура

Сервер использует четырёхуровневую архитектуру коллекций в Qdrant:

### 1. `1c_objects_meta` - Метаданные объектов

Хранит информацию об объектах конфигурации:
- Имена объектов и синонимы
- Описания и комментарии
- Структура (реквизиты, табличные части)
- Связи между объектами

**Мультивекторный поиск** по 5 векторам:
- `object_name` - имя объекта
- `friendly_name` - синоним
- `description` - описание
- `structure` - структура объекта
- `relationships` - связи с другими объектами

### 2. `1c_modules_full` - Полные модули

Хранит метаданные модулей объектов:
- Тип модуля (МодульОбъекта, МодульФормы и т.д.)
- Список процедур и функций
- Количество строк кода
- Экспортные методы

**Важно:** Полный код модуля восстанавливается из коллекции `1c_procedures`.

### 3. `1c_code_chunks` - Чанки кода

Хранит фрагменты кода для детального поиска:
- Код чанка
- Номера строк (start_line, end_line)
- Список процедур/функций в чанке
- Индекс чанка в модуле

**Оптимизация:** Чанки содержат только имена процедур, не полный код.

### 4. `1c_procedures` - Процедуры и функции

Хранит отдельные процедуры и функции:
- Полный код процедуры/функции
- Сигнатура и параметры
- Метаданные (экспорт, модуль, строки)
- Список вызовов (calls_to)

**Преимущества:**
- Прямой доступ к коду процедуры
- Быстрый поиск (5-10 раз быстрее чанков)
- Экономия места (50-60%)

### 5. `1c_syntax_help` - Синтакс-помощник

Хранит документацию по синтаксису платформы 1С:
- Глобальные функции
- Методы объектов
- Свойства объектов

## 🛠️ Инструменты (Tools)

### Поиск объектов

**`search_1c_objects`**
- Поиск объектов по описанию или назначению
- Мультивекторный поиск по 5 векторам
- Фильтрация по типу объекта

**Примеры:**
```
search_1c_objects("справочник номенклатуры")
search_1c_objects("документ продажи", object_type="Документ")
```

### Поиск в коде

**`search_1c_code`**
- Семантический поиск по коду модулей и чанкам
- Фильтрация по типу объекта, модуля
- Возвращает фрагменты кода с контекстом

**Примеры:**
```
search_1c_code("проверка реквизитов перед записью")
search_1c_code("обработка проведения", object_type="Документ")
```

### Поиск процедур

**`search_1c_procedures`** (старый метод)
- Поиск процедур через модули
- Возвращает список процедур с сигнатурами

**`search_procedures_direct`** (рекомендуется)
- Прямой поиск в коллекции процедур
- В 5-10 раз быстрее
- Возвращает полный код процедур

**Примеры:**
```
search_procedures_direct("процедура расчета остатков")
search_procedures_direct("проверка реквизитов", object_type="Справочник")
search_procedures_direct("обработка события", is_export_only=True)
```

### Получение кода

**`find_procedure_code`**
- Получить код конкретной процедуры по имени
- Точный поиск по объекту и имени процедуры

**`get_module_full_code`**
- Получить полный код модуля
- Восстанавливает код из коллекции процедур

**`list_object_modules`**
- Список всех модулей объекта с деталями
- Количество процедур, функций, экспортных методов

**Примеры:**
```
find_procedure_code("Справочник", "Номенклатура", "ПриЗаписи")
get_module_full_code("Справочник", "Номенклатура", "МодульОбъекта")
list_object_modules("Документ", "ЗаказПокупателя")
```

### Анализ зависимостей

**`analyze_procedure_calls`**
- Анализ вызовов процедуры
- Что вызывает эта процедура
- Кто вызывает эту процедуру

**`find_similar_procedures`**
- Поиск похожих процедур через эмбеддинги
- Поиск дублирующегося кода
- Показывает степень похожести

**Примеры:**
```
analyze_procedure_calls("Справочник", "Номенклатура", "ПриЗаписи")
find_similar_procedures("Документ", "ЗаказПокупателя", "ПриЗаписи", limit=5)
```

### Диагностика

**`diagnose_database`**
- Проверка состояния коллекций
- Статистика по объектам и модулям
- Поиск объектов по паттерну

**Пример:**
```
diagnose_database()
diagnose_database("Заказ")
```

### Метаданные

**`list_metadata_objects`** — сводка по типам объектов или перечень объектов типа (фильтр по имени/синониму)

**`search_by_structure`** — поиск по реквизитам, типам (в т.ч. в составных типах), ТЧ;
`indexed=True` — только индексируемые поля, объекты сортируются по их количеству

**`find_object_references`** — где используется объект: типы реквизитов/измерений/ресурсов, владельцы,
ввод на основании, движения + процедуры с обращениями `Справочники.Имя` / `Справочник.Имя`

**Примеры:**
```
list_metadata_objects()
list_metadata_objects("РегистрСведений", name_filter="цен")
search_by_structure(object_type="РегистрСведений", indexed=True, limit=5)
find_object_references("Справочник", "Номенклатура")
```

> Признаки полей (индексирование, проверка заполнения, ведущее, основной отбор) появляются после
> повторного парсинга и загрузки конфигурации обновлённой версией парсера.

### Проверка кода и стандарты

**`bslcheck_code`** — проверка кода, переданного текстом: BSL Language Server + проверки по стандартам.
Ответ — построчный список «строка:колонка [правило] сообщение», агент исправляет код и повторяет проверку.

**`bslcheck_analyze`** — то же для `.bsl` файла из примонтированной папки (`/workspaces`), файл не изменяется

**`bslcheck_format`** — форматирование (код текстом или файл), результат возвращается текстом

**`get_dev_standards`** — стандарты по теме из папки `standards/` (включая `1C_DEVELOPMENT_RULES.md`)
(монтируются в `/docs` и `/standards`). Также доступны ресурс `standards://<файл>` и промпт `develop_1c`.

Настройки BSL Language Server — `mcp/.bsl-language-server.json` (язык сообщений, параметры диагностик).

**Примеры:**
```
get_dev_standards("запросы")
bslcheck_code("Процедура Тест()
    Сообщить(Ссылка.ПолучитьОбъект().Наименование);
КонецПроцедуры")
```

### Синтакс-помощник

**`bslsyntax_search_global_function`**
- Поиск встроенных функций платформы
- Синтаксис, параметры, примеры

**`bslsyntax_search_method`**
- Поиск методов объектов
- ТаблицаЗначений, Запрос, СписокЗначений и т.д.

**`bslsyntax_search_property`**
- Поиск свойств объектов
- Описания и типы свойств

**`bslsyntax_get_details`**
- Детальная информация о синтаксисе
- Параметры, возвращаемые значения, примеры

**Примеры:**
```
bslsyntax_search_global_function("длина строки")
bslsyntax_search_method("ТаблицаЗначений", "добавить строку")
bslsyntax_search_property("колонки", "ТаблицаЗначений")
bslsyntax_get_details("СтрДлина", "function")
```

## ⚙️ Конфигурация

Конфигурация задается в `config.py` и через переменные окружения:

### Переменные окружения

**Qdrant:**
```bash
QDRANT_HOST=localhost
QDRANT_PORT=6333
```

**Embedding Service:**
```bash
EMBEDDING_SERVICE_URL=http://localhost:5000
```

**Сервер:**
```bash
SERVER_HOST=0.0.0.0
SERVER_PORT=9000
SERVER_NAME="MCP 1C RAG Server"
```

**Параметры поиска:**
```bash
DEFAULT_SEARCH_LIMIT=5
MAX_SEARCH_LIMIT=20
MIN_SEARCH_LIMIT=1
```

**Таймауты:**
```bash
EMBEDDING_REQUEST_TIMEOUT=30
HEALTH_CHECK_TIMEOUT=5
```

### Файл `.env`

Создайте файл `.env` в папке `mcp/`:

```env
QDRANT_HOST=localhost
QDRANT_PORT=6333
EMBEDDING_SERVICE_URL=http://localhost:5000
SERVER_PORT=9000
DEFAULT_SEARCH_LIMIT=5
```

- **Прямой поиск процедур** - 5-10 раз быстрее поиска в чанках

## 🐛 Решение проблем

### Сервер не запускается

**Проблема:** Ошибка подключения к Qdrant

**Решение:**
1. Проверьте что Qdrant запущен: `curl http://localhost:6333/health`
2. Проверьте переменные окружения `QDRANT_HOST` и `QDRANT_PORT`

### Embedding service недоступен

**Проблема:** Ошибка при генерации эмбеддингов

**Решение:**
1. Проверьте что embedding service запущен: `curl http://localhost:5000/health`
2. Проверьте переменную окружения `EMBEDDING_SERVICE_URL`

### Коллекции не найдены

**Проблема:** Ошибка "Collection not found"

**Решение:**
1. Убедитесь что данные загружены через loader
2. Проверьте имена коллекций в `config.py`
3. Используйте `diagnose_database()` для проверки

### Низкая скорость поиска

**Проблема:** Медленный поиск

**Решение:**
1. Используйте `search_procedures_direct` вместо `search_1c_procedures`
2. Уменьшите `limit` в запросах
3. Используйте фильтры для сужения области поиска

## 💡 Советы по использованию

### Выбор инструмента

- **Поиск объекта** → `search_1c_objects`
- **Поиск кода** → `search_1c_code`
- **Поиск процедуры** → `search_procedures_direct`
- **Получение кода** → `find_procedure_code` или `get_module_full_code`
- **Анализ зависимостей** → `analyze_procedure_calls`
- **Поиск синтаксиса** → `bslsyntax_search_global_function`, `bslsyntax_search_method`
- **Список объектов** → `list_metadata_objects`
- **Влияние изменений** → `find_object_references`
- **Стандарты перед написанием кода** → `get_dev_standards`
- **Проверка написанного кода** → `bslcheck_code`

### Оптимизация запросов

- Используйте фильтры (`object_type`, `object_name`) для сужения области поиска
- Уменьшайте `limit` если нужны только топ-результаты
- Для быстрого поиска используйте `search_procedures_direct`

## 📝 Формат ответов

Все инструменты возвращают текст в формате Markdown с:
- Структурированной информацией
- Блоками кода (```bsl)
- Эмодзи для визуального разделения
- Метаданными (релевантность, строки, параметры)
