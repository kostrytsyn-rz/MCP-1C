# Базовые практики разработки 1С

Краткая выжимка распространённых требований стандартов разработки 1С (ИТС) для агента.
Дополняйте и переопределяйте под свою команду.

## Чтение реквизитов ссылок

- Не получайте объект целиком (`Ссылка.ПолучитьОбъект()`) ради чтения одного-двух реквизитов:
  это читает все табличные части и реквизиты объекта из базы.
- Для чтения реквизитов используйте `ОбщегоНазначения.ЗначениеРеквизитаОбъекта(Ссылка, "Реквизит")`
  и `ОбщегоНазначения.ЗначенияРеквизитовОбъекта(Ссылка, "Реквизит1, Реквизит2")` (БСП) или запрос.
- Избегайте цепочек разыменования `Документ.Контрагент.ГоловнойКонтрагент.ИНН` в цикле — каждое
  обращение через точку может выполнять запрос к базе.
- `ПолучитьОбъект()` нужен только когда объект будет изменяться и записываться.

## Запросы

- Не выполняйте запросы в цикле: соберите параметры в массив/таблицу и выполните один запрос
  (`В (&Массив)`, соединение с временной таблицей).
- Не используйте `ВЫБРАТЬ *` — перечисляйте нужные поля.
- Условия накладывайте в параметрах виртуальных таблиц (`Остатки(&Период, Склад = &Склад)`),
  а не в `ГДЕ`.
- Учитывайте индексы: отбор и соединение по индексируемым полям (см. `search_by_structure(indexed=True)`).
- Для проверки существования используйте `ВЫБРАТЬ ПЕРВЫЕ 1`.

## Транзакции и блокировки

- `НачатьТранзакцию()` всегда в паре с `ЗафиксироватьТранзакцию()` / `ОтменитьТранзакцию()`
  внутри `Попытка ... Исключение`; в блоке `Исключение` — отмена транзакции и `ВызватьИсключение`.
- Перед чтением данных для последующей записи устанавливайте управляемую блокировку
  (`БлокировкаДанных`), а не полагайтесь на чтение без блокировки.
- Не выполняйте в транзакции длительные операции и обращения к внешним ресурсам.

## Клиент-сервер и формы

- Минимизируйте серверные вызовы: объединяйте обращения к серверу в одну процедуру `&НаСервере`.
- Используйте `&НаСервереБезКонтекста`, если контекст формы не нужен.
- Не передавайте на клиент объекты и большие коллекции — только нужные значения.

## Сообщения, даты, поиск

- Сообщения пользователю — `ОбщегоНазначения.СообщитьПользователю()` (БСП), а не `Сообщить()`.
- Текущая дата на сервере — `ТекущаяДатаСеанса()`, а не `ТекущаяДата()`.
- Не ищите элементы по наименованию (`НайтиПоНаименованию`): используйте предопределённые
  элементы, коды или ссылки.

## Обработка ошибок

- Не подавляйте исключения пустым блоком `Исключение`: как минимум запишите
  `ЗаписьЖурналаРегистрации` с `ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())`.
- Не оборачивайте в `Попытка` код, ошибки которого должны прерывать операцию.

## Проверка кода

- После изменения кода вызывайте `bslcheck_code(code)`: ошибки BSL Language Server и замечания
  по стандартам возвращаются построчно — исправьте их до показа результата пользователю.
