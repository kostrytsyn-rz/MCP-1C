## 🎯 Обзор

Веб-интерфейс (Streamlit) для загрузки распарсенных конфигураций 1С в Qdrant:

- 📦 Загрузка ZIP архивов с результатами парсинга
- 🧠 Генерация эмбеддингов через embedding service
- 💾 Загрузка в Qdrant с оптимизацией памяти
- 🔄 Инкрементальное обновление для ускорения повторных загрузок
- ✅ Checkpoint система для возобновления прерванной загрузки

---

### Через Docker

```bash
docker-compose up -d loader
```

Откройте http://localhost:8501

## ✨ Возможности

### Основные функции

- ✅ **Streaming загрузка** - обработка данных чанками для минимизации использования ОЗУ
- ✅ **Инкрементальное обновление** - обновление только изменённых объектов (ускорение в 10-20 раз)
- ✅ **Checkpoint система** - возобновление прерванной загрузки с места остановки
- ✅ **Retry логика** - автоматические повторные попытки при ошибках
- ✅ **Переиспользование эмбеддингов** - для чанков процедур используются эмбеддинги из коллекции PROCEDURES

### Оптимизации

- 💾 **Минимальное использование ОЗУ** - обработка чанками по 50 объектов
- ⚡ **Параллельная обработка** - использование ThreadPoolExecutor для ускорения
- 🔄 **Connection pooling** - переиспользование HTTP соединений к embedding service
- 📊 **Детальная статистика** - метрики производительности в реальном времени

## 🏗️ Архитектура

### Процесс загрузки (3 фазы)

**Фаза 1: Сбор данных**
- Параллельное чтение и парсинг файлов из архива
- Загрузка `modules_metadata.json` для использования правильных границ процедур/функций
- Анализ изменений (при инкрементальном режиме)

**Фаза 2/3: Streaming эмбеддинги + загрузка**
- Обработка объектов чанками
- Генерация эмбеддингов через embedding service
- Создание точек и немедленная загрузка в Qdrant
- Очистка памяти после каждого чанка

### Коллекции Qdrant

**1c_objects_meta** - метаданные объектов
- Векторы: `object_name`, `friendly_name`, `description`
- Payload: метаданные, реквизиты, табличные части, связи

**1c_modules_full** - метаданные модулей
- Векторы: `module_name`, `code` (сокращенный)
- Payload: информация о процедурах/функциях (signature, params, start_line, end_line)

**1c_code_chunks** - чанки кода
- Векторы: `code` (полный код чанка)
- Payload: информация о типе чанка, процедуре, модуле
- Для чанков типа "procedure" используются эмбеддинги из PROCEDURES

**1c_procedures** - процедуры и функции
- Векторы: `code` (полный код процедуры/функции)
- Payload: полный код, метаданные (signature, params, calls_to)

## ⚙️ Конфигурация

### Переменные окружения

```bash
QDRANT_HOST=localhost          # Хост Qdrant
QDRANT_PORT=6333              # Порт Qdrant
EMBEDDING_SERVICE_URL=http://localhost:5000  # URL embedding service
COLLECTION_OBJECTS=1c_objects_meta           # Имена коллекций (должны совпадать с mcp)
COLLECTION_MODULES=1c_modules_full
COLLECTION_CHUNKS=1c_code_chunks
COLLECTION_PROCEDURES=1c_procedures
CHUNK_SIZE=1000                # Строк кода в чанке
MIN_LINES_FOR_CHUNKING=800     # Минимум строк модуля для разбиения на чанки
```

Значения читаются в `config.py`.

### Отчёт об изменениях (инкрементальное обновление)

Перед загрузкой показывается сводная таблица: новые, изменённые (метаданные / модули) и удалённые
объекты, добавленные / изменённые / удалённые модули. Таблица фильтруется по действию и типу объекта,
есть поиск по имени и выгрузка в CSV (`changes_report.csv`). Отчёт доступен и после подтверждения, и в
итогах загрузки.

Если модель эмбеддингов сменилась (другая размерность векторов), инкрементальная загрузка остановится
с подсказкой выполнить полную перезагрузку.

### Параметры загрузки

**Эмбеддинги:**
- `embedding_batch_size` - размер батча для генерации эмбеддингов (8-500)
- `max_retries` - максимальное количество повторных попыток (1-10)
- `base_timeout` - базовый таймаут для запросов в секундах (60-600)

**Загрузка в Qdrant:**
- `upload_batch_size` - размер батча для загрузки точек (10-1000)
- `scroll_batch_size` - размер страницы для Scroll API (100-5000)

**Обработка данных:**
- `max_workers` - количество потоков для параллельной обработки (2-20)
- `max_chunk_lines` - максимальный размер чанка процедуры в строках (200-1000)
- `overlap_lines` - размер перекрытия между чанками длинных процедур (10-200)
- `max_context_lines` - размер контекста модуля из начала (20-150)

### Пресеты настроек

**Слабый ПК** (2-4 ядра, 8GB RAM, CPU):
- Небольшие батчи, меньше потоков
- Оптимизировано для ограниченных ресурсов

**Средний ПК** (4-8 ядер, 16GB RAM):
- Баланс между скоростью и использованием ресурсов

**Мощный ПК** (8+ ядер, 32GB+ RAM, GPU):
- Большие батчи, больше потоков
- Максимальная производительность

## 🔄 Процесс загрузки

### 1. Подготовка данных

Используйте парсер (контейнер `parser-1c`, запускается `start.bat` проекта MCP-1C_INIT) для создания
ZIP архива с результатами парсинга: http://localhost:8504.

```
parsed_config.zip
├── objects.csv              # Список объектов
├── modules_metadata.json    # Метаданные модулей
├── modules/                 # BSL файлы
└── metadata/               # JSON метаданные
```

### 2. Загрузка в Qdrant

1. Откройте веб-интерфейс загрузчика
2. Загрузите ZIP архив
3. Настройте параметры (или используйте пресет)
4. Включите/выключите инкрементальное обновление
5. Запустите загрузку

### 3. Мониторинг

Веб-интерфейс показывает:
- Прогресс загрузки в реальном времени
- Статистику по каждому чанку
- Использование памяти
- Время обработки эмбеддингов и загрузки в Qdrant

## 🔍 Инкрементальное обновление

При включенном режиме:

1. **Анализ изменений** - сравнение хешей объектов и модулей
2. **Определение изменений** - только изменённые объекты обрабатываются заново
3. **Удаление устаревших данных** - удаляются чанки и процедуры изменённых модулей
4. **Загрузка новых данных** - обновлённые объекты загружаются заново

**Преимущества:**
- Ускорение в 10-20 раз для небольших изменений
- Экономия ресурсов GPU/CPU
- Быстрое обновление индекса

---

## 💡 Советы по использованию

### Оптимизация производительности

1. **Для больших конфигураций** - увеличьте `embedding_batch_size` и `upload_batch_size`
2. **При ограниченной памяти** - уменьшите размеры батчей и количество потоков
3. **Для повторных загрузок** - используйте инкрементальное обновление
4. **При сбоях** - используйте checkpoint для возобновления

### Решение проблем

**Медленная загрузка:**
- Увеличьте `max_workers` (если есть ресурсы)
- Увеличьте размеры батчей
- Проверьте производительность embedding service

**Ошибки соединения:**
- Проверьте доступность Qdrant и embedding service
- Увеличьте `base_timeout`
- Проверьте сетевое соединение

**Нехватка памяти:**
- Уменьшите `embedding_batch_size`
- Уменьшите `upload_batch_size`
- Уменьшите `max_workers`

## 🔗 Интеграция

### С парсером

1. Парсер создаёт ZIP архив с результатами парсинга
2. Загрузчик читает этот архив и загружает данные в Qdrant
3. MCP Server предоставляет данные через MCP протокол для AI агентов

### С MCP Server

После загрузки данные доступны для:
- Семантический поиск по коду
- RAG-запросы к документации
- Анализ зависимостей между процедурами

## 🔧 Технические детали

### Генерация ID

Используется детерминированная генерация ID на основе SHA256 хеша строкового ключа. Это гарантирует стабильные ID при повторных загрузках.

### Оптимизация памяти

- Обработка объектов чанками по 50 штук
- Немедленная загрузка в Qdrant после генерации эмбеддингов
- Принудительная очистка памяти (`gc.collect()`) после каждого чанка
- Переиспользование эмбеддингов для чанков процедур

### Connection pooling

HTTP сессия с connection pooling для переиспользования соединений к embedding service. Уменьшает накладные расходы на установку соединений.

## 📊 Метрики

Загрузчик показывает следующие метрики:

- **Объекты** - количество обработанных объектов
- **Модули** - количество обработанных модулей
- **Чанки** - количество созданных чанков кода
- **Процедуры** - количество индексированных процедур/функций
- **Время обработки** - время генерации эмбеддингов и загрузки
- **Скорость загрузки** - точек в секунду
- **Использование памяти** - текущее использование ОЗУ (если доступно)

## 🔐 Безопасность

- Локальная обработка данных (не отправляются в облако)
- Данные хранятся только в локальной/контролируемой Qdrant
- Embedding service должен быть доступен только локально
