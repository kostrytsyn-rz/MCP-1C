# 🎨 Веб-интерфейс парсера конфигураций 1С

Удобный веб-интерфейс для парсинга и интеллектуального объединения конфигураций 1С с расширениями.

---

## 🚀 Быстрый старт

### Запуск через Docker (рекомендуется)

```bash
# Из корня проекта
docker-compose up parser
```

После запуска откройте в браузере: **http://localhost:8502**

### Остановка

```bash
docker-compose stop parser
```

---

## 📋 Возможности

### ✅ Что умеет интерфейс:

1. **Выбор конфигураций из папки `in_conf/`**
   - Основная конфигурация (ZIP или распакованная папка)
   - Расширения (любое количество, ZIP или папки)
   - Автоматическая валидация (проверка Configuration.xml)
   - Поддержка до 2 уровней вложенности папок

2. **Управление расширениями**
   - Добавление любого количества расширений
   - Изменение порядка применения (⬆️⬇️)
   - Удаление ненужных расширений (🗑️)
   - Порядок влияет на последовательность объединения

3. **Быстрые действия**
   - 🗑️ Очистить всё - полный сброс
   - Встроенное удаление файлов (крестик ✖️)

4. **Парсинг и объединение**
   - Реальный парсинг с `Config1CParser`
   - Отображение всех этапов парсинга в реальном времени
   - Интеллектуальное объединение с `IntelligentConfigMerger` (опционально)
   - Поддержка аннотаций (`&Перед`, `&После`, `&Вместо`, `&ИзменениеИКонтроль`)
   - Последовательное применение расширений

5. **Сохранение результатов в `out_conf/`**
   - Автоматическое сохранение в `out_conf/parsed_<имя_конфигурации>/`
   - `<имя_конфигурации>.zip` - архив основной конфигурации
   - `<имя_расширения>.zip` - архив каждого расширения
   - `merged.zip` - объединённая конфигурация (если включено объединение)
   - Папки с исходниками: `markdown/`, `modules/`, `metadata/`

## 📖 Инструкция по использованию

### Шаг 1: Подготовка конфигураций

Выгрузите конфигурации 1С и поместите их в папку `in_conf/`:

**Вариант 1: ZIP-архивы**
```
in_conf/
├── config_ut.zip          (основная конфигурация)
├── extension_aa.zip       (расширение 1)
└── extension_bb.zip       (расширение 2)
```

**Вариант 2: Распакованные папки**
```
in_conf/
├── ut/                    (основная конфигурация)
│   ├── Configuration.xml
│   ├── Documents/
│   └── Catalogs/
├── ut_aa/                 (расширение 1)
│   ├── Configuration.xml
│   └── ...
└── ut_bb/                 (расширение 2)
    ├── Configuration.xml
    └── ...
```

**Вариант 3: Комбинация**
```
in_conf/
├── config_ut.zip
├── extensions/
│   ├── extension_aa/     (распакованная папка)
│   └── extension_bb.zip
```

### Шаг 2: Выбор основной конфигурации

1. Откройте веб-интерфейс: http://localhost:8502
2. В выпадающем списке "Основная конфигурация" выберите нужный файл/папку
3. Дождитесь валидации (✅ или ❌)
4. В верхней панели обновится статус загрузки

### Шаг 3: Добавление расширений (опционально)

1. В выпадающем списке "Расширения" выберите расширение
2. Нажмите "➕ Добавить расширение"
3. Расширение автоматически добавится в список
4. Повторите для других расширений

**Управление списком:**
- ⬆️ - переместить расширение выше
- ⬇️ - переместить расширение ниже
- 🗑️ - удалить расширение

### Шаг 4: Порядок расширений

Порядок **критически важен**! Расширения применяются последовательно:

```
Основная конфигурация (ut)
  ↓
+ Расширение 1 (ut_aa)  ← применяется первым
  ↓
+ Расширение 2 (ut_bb)  ← применяется вторым
  ↓
= merged.zip (объединённая конфигурация)
```

### Шаг 5: Запуск парсинга

1. Проверьте настройки:
   - ☑️ **Объединить конфигурации** - создать merged.zip (опционально, только если есть расширения)

2. Нажмите **"🚀 Начать парсинг"**

3. Наблюдайте за процессом в реальном времени:
   - Этапы парсинга каждой конфигурации
   - Обработка типов объектов (Справочники, Документы и т.д.)
   - Сохранение результатов
   - Статистика объектов

4. После завершения кнопка изменится на **"🔄 Парсить заново"**

### Шаг 6: Получение результатов

После завершения парсинга результаты автоматически сохраняются в:
```
out_conf/parsed_<имя_основной_конфигурации>/
```

**Структура папки с результатами:**
```
out_conf/parsed_config_ut/
├── config_ut.zip          # Архив основной конфигурации
├── extension_aa.zip       # Архив расширения 1
├── extension_bb.zip       # Архив расширения 2
├── merged.zip             # Объединённая конфигурация (если включено)
├── config_ut/             # Исходники основной
│   ├── markdown/
│   ├── modules/
│   ├── metadata/
│   └── objects.csv
├── extension_aa/          # Исходники расширения 1
└── extension_bb/          # Исходники расширения 2
```

Вы можете сразу использовать эти файлы или скопировать в другое место.

## 🎯 Примеры использования

### Пример 1: Простая конфигурация без расширений

1. Поместить `config_ut.zip` в `in_conf/`
2. Выбрать в интерфейсе: `config_ut.zip`
3. Расширения: _не добавляем_
4. Парсинг

**Результат в `out_conf/parsed_config_ut/`:**
- `config_ut.zip` - архив
- `config_ut/` - исходники

---

### Пример 2: Конфигурация с одним расширением

1. Поместить в `in_conf/`:
   - `config_ut.zip` (основная)
   - `extension_aa.zip` (расширение)
2. Выбрать основную: `config_ut.zip`
3. Добавить расширение: `extension_aa.zip`
4. ☑️ Объединить конфигурации
5. Парсинг

**Результат в `out_conf/parsed_config_ut/`:**
- `config_ut.zip` - основная
- `extension_aa.zip` - расширение
- `merged.zip` - объединённая конфигурация
- Папки с исходниками для каждой

---

### Пример 3: Конфигурация с несколькими расширениями и папками

1. Структура `in_conf/`:
```
in_conf/
├── config_ut.zip
└── extensions/
    ├── extension_aa/     (распакованная папка)
    ├── extension_bb.zip
    └── extension_custom.zip
```

2. Выбрать основную: `config_ut.zip`
3. Добавить расширения в нужном порядке:
   - `extension_aa/` (базовое)
   - `extension_bb.zip` (дополнительное)
   - `extension_custom.zip` (кастомное)
4. ☑️ Объединить конфигурации
5. Парсинг

**Результат в `out_conf/parsed_config_ut/`:**
- `config_ut.zip`
- `extension_aa.zip`
- `extension_bb.zip`
- `extension_custom.zip`
- `merged.zip` ← ut + ut_aa + ut_bb + ut_custom
- Папки с исходниками

## ⚙️ Что происходит при парсинге?

### 1. Распаковка архивов
Каждый ZIP-архив распаковывается во временную папку.

### 2. Парсинг основной конфигурации
```
Config1CParser → modules/, metadata/, objects.csv
```

### 3. Парсинг расширений
```
Config1CParser → modules/, metadata/, objects.csv (для каждого)
```

### 4. Интеллектуальное объединение (если включено)
```
IntelligentConfigMerger:
  - Объединение метаданных (JSON)
  - Объединение кода с аннотациями:
    • &Перед - вставка в начало
    • &После - вставка в конец
    • &Вместо - замена тела процедуры
    • &ИзменениеИКонтроль - точечные изменения
  - Генерация markdown
  - Объединение CSV
```

### 5. Сохранение результатов
Все результаты сохраняются в папку `out_conf/parsed_<имя>/`:
- Исходники (markdown, modules, metadata)
- ZIP-архивы для каждой конфигурации/расширения

## ⚠️ Важные замечания

### О производительности

Парсинг большой конфигурации (УТ 11.5):
- Основная конфигурация: **~5-10 минут**
- Расширение: **~1-3 минуты**
- Объединение: **~2-5 минут**

**Итого:** 10-20 минут для полного цикла


## 🔗 Интеграция с Loader

После парсинга вы можете загрузить результаты в Qdrant:

1. Найдите результаты в папке `out_conf/parsed_<имя>/`
2. Скопируйте нужный ZIP (например, `merged.zip`) в папку `data/`
3. Откройте **Loader** по адресу http://localhost:8501
4. Выберите скопированный архив
5. Дождитесь векторизации и загрузки в Qdrant
6. Используйте **MCP Server** для RAG-запросов через AI агентов
